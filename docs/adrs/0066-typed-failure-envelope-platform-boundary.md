# ADR-0066: Typed Failure Envelope Platform Boundary

- Status: Accepted
- Date: 2026-08-27
- Deciders: TemperPaw maintainers
- Related:
  - TemperPaw issue #11
  - Temper issue #21
  - Temper PR #66
  - Temper ADR-0187: Versioned application failure envelopes
  - ADR-0005: Temper-native orchestration

## Context

TemperPaw previously pinned Temper commit
`e8ff002bde3e9512385c2856d733210600e7c253`. That revision predates the
versioned `failure_v1` application envelope and declarative
`[[action.triggers.failure_routes]]` metadata. Advancing only the server or
only guest SDK dependencies would split the parser, verifier, JIT metadata,
runtime routing, code generation, and WASM ABI across incompatible revisions.

Existing TemperPaw applications use the legacy `on_failure` callback contract.
This platform upgrade must make typed routes available without forcing an
unreviewed migration of those product flows.

## Decision

TemperPaw pins every tracked Temper runtime, tooling, verifier, code generator,
and `temper-wasm-sdk` dependency to one immutable `nikstern/temper` commit that
contains the merge of PR #66 and the canonical local-module closure fix from
PR #75:

`e3dfe852e7a7373cef8bddfe2e3b8bcad8f94a0a`

The production source remains `https://github.com/nikstern/temper.git`, the
same source already used by TemperPaw production. The canonical pin and
discovery scope remain in `.temper-kernel.toml`; the scope now includes tracked
reference-project manifests as well as the workspace, crates, and OS apps.
Existing root and nested WASM lockfiles are regenerated by Cargo through
`scripts/sync-temper-kernel`, never hand-edited.

The later commit is required because a real local-catalog boot proved that the
PR #66 merge commit verified typed module bindings against only the root app
schema even though generation and binding use the dependency-complete local
module closure. Temper PR #75 makes local installation resolve that same
canonical closure before accepting the artifact-bound proof.

A minimal `FailureRouteProbe` conformance fixture defines an integrity route to
a callback whose exact ABI is:

```toml
params = [{ name = "failure", type = "failure_v1" }]
```

The fixture must parse, enter the Temper verification model, compile into the
server registry/JIT table, and execute a real missing-WASM failure through the
typed callback. A separate unchanged top-level `[[integration]]` fixture must
continue to execute `on_failure`.

## Compatibility Boundary

- Existing product specs stay on legacy `on_failure` in this change.
- New specs may opt into typed `failure_routes` one trigger at a time.
- A trigger may not mix typed routes with legacy `on_failure`; Temper rejects
  that ambiguous configuration.
- Typed callback actions accept exactly one `failure_v1` parameter named
  `failure`.
- Undeclared failure categories fail closed; retryability is data, not an
  instruction to replay an operation.
- Product-flow migrations require their own state-machine, Cedar, WASM, and
  end-to-end review.

## Consequences

### Positive

- TemperPaw apps can adopt bounded failure categories without parsing
  diagnostic strings.
- Host and guest failure contracts resolve from one immutable commit.
- Legacy apps continue to load and execute during incremental migration.
- CI checks the complete tracked Temper manifest and lockfile surface.

### Negative

- Nested WASM lockfiles gain the shared `temper-failure` package even before
  individual product flows use typed routes.
- Future Temper upgrades must continue to move all runtime and guest pins
  together.
- `Paw.FS.File` must explicitly declare its existing mutable stream behavior;
  Paw FS ADR-003 records that app-scoped contract.
- TemperPaw startup handles `MigrationRequired` as a fatal, human-readable
  reconciliation error so a governed stream migration cannot be bypassed.

## Verification Requirements

- `scripts/sync-temper-kernel --check` reports no mixed or stale source.
- The typed and legacy conformance tests both pass from checked-in lockfiles.
- The full native workspace and every checked-in OS-app WASM module build with
  `--locked`.
- `temperpaw-server` boots cleanly, and the conformance dispatches reach
  `Failed` through their respective typed and legacy callbacks.

## Non-Goals

- Migrating any shipped TemperPaw product flow from `on_failure`.
- Adding automatic retries or imperative recovery orchestration.
- Changing the production Temper repository or introducing a fork-only pin.
